Beyond classic RAG: long context, CAG, agentic RAG, Open Knowledge Format

Track: AI/LLM systems. Drop 3 measured RAG, drop 4 improved it; this is about when to use something other than (or on top of) classic RAG.
Classic RAG = search a chunked index at question time, paste the top chunks into the prompt. It is not the only way to give a model knowledge. Four newer options, and they are not all the same kind of thing: two are about where knowledge sits (in the context window), one is about who drives retrieval (an agent), and one (OKF) is a file format for the knowledge itself.

What it is and the problem it solves

ApproachOne-line ideaProblem it solves
Long context (stuff it all in)Models now accept hundreds of thousands of tokens, so for a small corpus just put the whole thing in the promptNo index to build; no 'the right chunk was not retrieved' failures
Cache-augmented generation (CAG)Load a small, stable knowledge base into the context once, keep the model's precomputed state (KV cache) and reuse it for every questionRemoves retrieval latency and retrieval errors for bounded knowledge; reuse makes long context affordable
Agentic RAGThe LLM decides whether to search, which source/tool to use, rewrites and searches again until it has enoughMulti-step, multi-source questions that one fixed search cannot answer
Open Knowledge Format (OKF)Google Cloud's open spec: organizational knowledge as plain markdown files with YAML frontmatter, in a folder, linked to each other, kept in gitCompany knowledge (tables, metrics, APIs, playbooks) is scattered across wikis and catalogs; agents need it in one portable, trustworthy, readable form

Verified on OKF: it is real and recent. Google Cloud published v0.1 in mid-2026 and v0.2 on 24 July 2026 (GitHub: GoogleCloudPlatform/open-knowledge-format). Every concept is one markdown file whose only required field is 'type'. v0.2 adds five trust signals: provenance ('sources'), who generated and who verified it ('generated', 'verified'), freshness ('stale_after'), lifecycle ('status'), and an 'Attested Computation' concept type. Important: OKF is not a replacement for RAG. It is a way to store and ship knowledge that an agent can then read directly, load into long context, or index for RAG. Google itself calls v0.1 'a starting point, not a finished standard'.

How it works

  1. Long contextSend all documents with the question. Simple, but you pay for every token on every call, latency grows with size, and models can still overlook facts buried in the middle of very long prompts.
  2. CAGFrom the paper 'Don't Do RAG: When Cache-Augmented Generation is All You Need for Knowledge Tasks' (Chan et al., WWW 2025): preload the whole bounded knowledge base, precompute the KV cache once, answer every query from it with no retrieval step. In managed APIs the practical cousin is prompt caching (drop 2): a fixed long prefix is cached and reused at a discount.
  3. Agentic RAGRetrieval becomes a tool the agent calls (drop 1 tool calling, drop 2 MCP). The agent can plan sub-questions, pick between a vector index, SQL, a web search or an API, check whether the results are enough, and search again. More accurate on hard questions; slower, costlier and harder to evaluate.
  4. OKFKnowledge is a folder: one markdown file per concept (a table, a metric, an API), YAML frontmatter for filterable fields (type, tags, status, sources, verified), links between files make a graph, and auto-generated index.md files let an agent walk one level at a time instead of loading everything (progressive disclosure). Humans review changes as pull requests.
Everyday comparison: an exam.
Classic RAG is an open-book exam where you flip to the index for each question. Long context is bringing the whole (thin) book and reading it every time. CAG is memorising that thin book the night before so you answer instantly. Agentic RAG is a research assignment: you go to the library, the internet and a phone call to a friend, as many trips as needed. OKF is the well-organised, labelled binder of company notes (with 'last checked by' stamps) that any of those students can use.

Pattern card: pick the knowledge strategy per question type

What it is
Route each kind of question to the cheapest approach that answers it reliably: cached context for small stable docs, classic RAG for big corpora, an agent only for multi-step questions.
Metaphor
A clinic: the nurse answers routine questions from memory, the GP looks things up, only complex cases go to the specialist team.
Real example
Google Cloud publishes OKF with sample bundles (GA4, Stack Overflow, Bitcoin datasets) produced by an agent; the CAG paper benchmarks preloaded context against RAG on QA datasets.
Use when
One assistant serves both FAQ-style and research-style questions; cost or latency budgets matter.
Do not use when
There is only one question type; then pick one approach and keep it simple.
Trade-offs
A router adds a step that can misclassify; each path needs its own evals.
Instruction to AI / a teammate
Put the 40-page product policy in a cached system prompt, keep hybrid RAG for the 20,000 support tickets, expose both plus the orders SQL view as tools to an agent that may make at most 4 tool calls, and report accuracy, p95 latency and cost per answer for each path on our golden set.

Real-world scenario and why it matters on the job

Google Cloud released OKF in 2026 with a proof-of-concept agent that reads BigQuery datasets and writes OKF bundles; the repository ships ready-to-browse bundles for the GA4 e-commerce, Stack Overflow and Bitcoin public datasets plus a graph visualiser. The motivation in their words: agents cannot answer questions about a company's own systems when the answers are scattered across wikis, code comments, catalogs and people's heads. The CAG paper (National Chengchi University and Academia Sinica, published at the ACM Web Conference 2025) shows that for a constrained knowledge base, preloading plus a reused KV cache can match or beat RAG with lower latency and less complexity.

On the job: as an FDE you will often be asked 'should we build RAG?' for a customer with 30 PDFs. Knowing that long context + caching may be cheaper and more accurate, and that the real problem is often messy, unowned knowledge (which an OKF-style, git-reviewed bundle fixes), saves weeks. CV tie-in: a camera-inspection assistant can keep the short defect catalogue in cached context while an agent queries the inspection database for today's counts.

FDE / architect interview angle

  • 'Context windows are huge now. Is RAG dead?' Strong answer: no, it depends on corpus size, change rate, cost and permissions. Small stable docs: long context + caching. Large, changing, permissioned corpora: RAG (per-user filtering is easier on an index). Multi-step: agentic. Back it with an eval and a cost-per-answer number.
  • 'When would you make RAG agentic?' Strong answer: when questions need planning or several sources; add guardrails (max steps, timeouts, budget), log every tool call, and evaluate trajectories, not just final answers.

Glossary

Context window
The maximum amount of text (in tokens) a model can read in one request.
Token
A small piece of text (roughly 3/4 of an English word) that models read and are billed by.
Long context
Putting a lot of material directly into the prompt instead of retrieving pieces.
KV cache
The model's internal precomputed state for text it has already read; reusing it skips re-reading that text.
CAG (cache-augmented generation)
Preload a bounded knowledge base into context, cache the KV state, answer without retrieval.
Prompt caching
A provider feature that stores a repeated prompt prefix so later calls are cheaper and faster (drop 2).
Agentic RAG
RAG where an agent decides when, where and how often to retrieve, using tools.
Trajectory
The sequence of steps and tool calls an agent took to reach an answer.
OKF
Open Knowledge Format: Google Cloud's open spec for knowledge as markdown + YAML frontmatter files.
YAML frontmatter
A small block of key: value fields at the top of a markdown file, readable by machines.
Bundle
In OKF, a folder of concept files shipped together (e.g. a git repo).
Provenance
Where a piece of information came from.
Progressive disclosure
Reading an overview first and opening details only when needed, to save context.
Golden set
A fixed list of questions with known good answers used to test the system (drop 3).
p95 latency
The response time that 95% of requests are faster than.
