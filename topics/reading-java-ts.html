How it works: one request through each stack

  1. Java / Spring Boot: annotations are the mapWords starting with @ work like Python decorators: they tell the framework what a class is (@RestController, @Service, @Repository, @Configuration). Spring creates these objects at startup and wires them together (dependency injection), so you rarely see new TicketService() written by hand.
  2. Next.js App Router: folders are the mapThe folder path is the URL: app/tickets/page.tsx is the /tickets page, layout.tsx wraps pages, app/api/tickets/route.ts is an API endpoint. Components are server components by default (run on the server, can read the database); a file starting with the 'use client' directive runs in the browser (clicks, state).
  3. React: components are functions that return UIA component takes props (inputs) and returns markup. useState holds data that changes, useEffect runs side effects after render. Think: a Python function that returns HTML and re-runs when its inputs change.
  4. Types are documentation you can trustJava and TypeScript enforce types (like Python type hints, but checked before running). Read the input and output types of a function first: they tell you what it does before you read its body.
Everyday comparison: a restaurant.
The controller is the waiter (takes the order, brings the plate, does not cook). The service is the chef (the actual rules and recipe). The repository is the pantry manager (fetches and stores ingredients). Dependency injection is the restaurant manager assigning staff to roles, instead of the chef hiring their own pantry manager. In Next.js, server components are cooks in the kitchen; client components are staff at your table.

Pattern card: layered architecture (controller / service / repository)

What it is
Split each request into three jobs: receive and respond (controller), apply business rules (service), read and write data (repository).
Metaphor
Waiter, chef, pantry manager.
Real example
Netflix standardised its Java backend services on Spring Boot (below), which is built around these layers and dependency injection.
Use when
Any business application expected to live more than a few months or be worked on by several people (or several AI agents).
Do not use when
One-off scripts, tiny prototypes, or simple Next.js pages that just display data.
Trade-offs
More files and indirection; in return each part is testable and replaceable (swap the database or the LLM provider in one place).
Instruction to AI / a teammate
Keep the ticket feature layered: a thin controller (or Next.js route handler) that validates input and calls TicketService, all business rules and LLM calls in TicketService, all database access in TicketRepository, dependencies passed in through the constructor so we can mock them in tests, and no database or secret access from client components.

Real-world scenario and why it matters on the job

Netflix: in the InfoQ talk How Netflix Really Uses Java, Netflix's Java platform team describes completely standardising on Spring Boot after migrating services off an older homegrown Guice-based stack, and adding Spring Boot Netflix modules for gRPC, security (AuthN/AuthZ), tracing and metrics. Netflix also open-sourced the DGS framework for building GraphQL services on Spring Boot. So when you open a large company's Java service, expect exactly the annotations, injection and layers in the table above. Next.js itself is built and maintained by Vercel, and the App Router folder-as-route convention is its default.

Why it matters: as a lead, you review architecture more than lines. Spotting business logic leaked into a controller, or a database query inside a client component, in AI-generated code, and asking for a fix in one sentence, is exactly the skill. It also lets you talk credibly with Java-heavy enterprise customers.

Where it shows up in code you'll read: the same endpoint three ways

# Python (FastAPI)
@app.get('/tickets/{id}')
def get_ticket(id: int, service: TicketService = Depends(get_service)):
    return service.find(id)
// Java (Spring Boot)
@RestController
class TicketController {
  private final TicketService service;                 // injected by Spring
  TicketController(TicketService service) { this.service = service; }

  @GetMapping('/tickets/{id}')   // real Java uses double quotes here
  TicketDto get(@PathVariable long id) { return service.find(id); }
}
// TypeScript (Next.js App Router): app/api/tickets/[id]/route.ts
export async function GET(req: Request, { params }) {
  const ticket = await ticketService.find(Number(params.id));
  return Response.json(ticket);
}
// A page instead: app/tickets/[id]/page.tsx is a server component that can call
// ticketService directly and return UI; mark only interactive parts as client components.

FDE / architect interview angle

  • Walk me through what happens when a request hits this Spring Boot service. Strong answer: security filters check the token (topic 1), the controller maps the URL and validates input, the injected service applies rules and calls other services or the LLM, the repository talks to the database, the DTO is serialised to JSON; plus where logging, tracing and error handling sit.
  • In Next.js, what runs on the server and what runs in the browser, and why does it matter? Strong answer: server components and route handlers run on the server (database, secrets, LLM keys stay there); client components run in the browser; leaking a secret or a heavy library into a client component is a security and performance bug.

Glossary

Spring Boot
The most common Java framework for web services; sets up servers, config and wiring for you.
Annotation
A Java @Label on a class or method that tells the framework how to treat it; like a Python decorator.
Controller
Code that receives HTTP requests and returns responses.
Service
Code holding business rules.
Repository
Code that reads and writes the database.
Dependency injection (DI)
Giving an object the things it needs from outside rather than creating them inside; makes testing and swapping easy.
DTO / record / entity
Plain data object sent over the wire / Java's compact data class / class mapped to a database table.
JPA / Prisma / SQLAlchemy
Libraries that map code objects to database tables (ORMs) in Java / TypeScript / Python.
Interface
A contract listing methods a class must provide.
Next.js App Router
Next.js routing where folders under app/ become URLs.
page.tsx / layout.tsx / route.ts
A page / a shared wrapper around pages / an API endpoint.
Server component
React component that runs on the server and can access databases and secrets.
Client component
React component marked with the use client directive; runs in the browser for interactivity.
Server action
A server function a Next.js form or button can call directly.
Props / state / hooks
Component inputs / data that changes over time / functions like useState and useEffect.
Middleware
Code that runs before requests reach routes, often for auth redirects.
Promise / CompletableFuture
A value that will arrive later (TypeScript / Java).
pom.xml / package.json
Java Maven / Node project files listing dependencies and scripts.
GraphQL / gRPC
Alternative API styles to REST: the client picks fields / fast binary calls between services.
