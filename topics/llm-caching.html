Caching in LLM and RAG apps: prompt, semantic, embedding caches

Track: AI/LLM systems.
LLM calls are the slowest and most expensive step in most AI apps (seconds and cents, versus milliseconds and fractions of a cent for a DB read). Caching is the single biggest cost lever an architect has.

What it is and the problem it solves

A RAG chatbot answering "what is our leave policy?" 2,000 times a day does the same expensive work each time: embed the question, search the vector DB, send a long prompt (system instructions + retrieved documents) to the model, wait several seconds, pay per token. Much of that work is repeated. There are four caches you can put in the path, each saving a different repeated piece:

CacheWhat is reusedHit whenSaves
Exact response cacheFinal answerIdentical question text (after normalising)Whole LLM call
Semantic cacheFinal answerA question that MEANS the same (embedding similarity above a threshold)Whole LLM call, even for reworded questions
Prompt (prefix) cache, provider-sideThe model's processing of the unchanged start of the promptSame long prefix sent again within minutesMost input-token cost and time-to-first-token; you still get a fresh answer
Embedding cacheVector for a piece of textSame text embedded again (re-indexing, repeated queries)Embedding API calls

How it works

  1. Semantic cacheEmbed the question, search a small vector index of past questions. If the closest one is similar enough (e.g. cosine similarity 0.95+), return its stored answer. Otherwise run the full pipeline and save the new pair. Redis, Azure Managed Redis or a vector DB usually holds it.
  2. Prompt cachingThe model provider remembers its internal processing of a prompt's prefix for a few minutes. Put everything static FIRST (system prompt, tool definitions, long reference docs) and the changing part (user question) LAST. Anthropic's cache reads cost 10% of normal input price (writes cost 25% more, default 5-minute lifetime); OpenAI / Azure OpenAI apply it automatically to long prompts; Amazon Bedrock and Vertex AI offer it for supported models.
  3. Embedding cacheKey = hash of the text + embedding model name, value = the vector. Avoids paying again when you re-index unchanged documents.
  4. InvalidationSame hard problem as drop 1: when the leave policy changes, cached answers are wrong. Use TTLs, and clear the semantic cache entries tied to a document when it is re-indexed.
Everyday comparison: a help desk with a FAQ binder.
Exact cache: the clerk recognises the exact same question and reads the same answer. Semantic cache: "how many holidays do I get?" and "what's my annual leave?" get the same FAQ page because they mean the same thing. Prompt cache: the clerk has already read the 200-page policy manual this morning, so they don't reread it for every caller; they only listen to the new question. Embedding cache: the index tabs on the binder are made once, not every time you open it.

Benefits

  • Large cost cuts and much faster responses on repeated work.
  • Prompt caching is nearly free to adopt: mostly reorder the prompt.
  • Smooths load and rate limits on the model endpoint.

Trade-offs and risks

  • Semantic cache can return a wrong answer for a question that looks similar but differs ("cancel my order" vs "can I cancel my order?"). Tune the threshold and evaluate.
  • Data leakage if cache keys are not scoped per user or tenant.
  • Stale answers after the source data changes; needs invalidation.

Pattern card: semantic cache in front of an LLM

What it is
A lookup by meaning, not exact text, that returns a stored answer when a sufficiently similar question was answered before.
Metaphor
Help-desk FAQ binder indexed by meaning.
Real example
Azure API Management ships an llm-semantic-cache-lookup policy for Azure OpenAI; Notion uses provider prompt caching (below).
Use when
High volume of repeated, non-personal questions over slowly changing content.
Do not use when
Answers are personal, actions have side effects, or data changes by the minute.
Trade-offs
Cost and speed in exchange for occasional wrong matches and invalidation work.
Instruction to give AI or a teammate
Put the static system prompt and tool definitions first so prompt caching hits, add a semantic cache in Redis keyed per tenant with a 0.95 similarity threshold and a 24-hour TTL, clear entries when a source document is re-indexed, and log hit rate and cost per request.

Real company: Notion

Notion was Anthropic's launch customer spotlight for prompt caching in Notion AI. Anthropic's Notion case study reports that prompt caching reduced Notion's costs by 90% and latency by up to 85%. Co-founder Simon Last: prompt caching makes Notion AI "faster and cheaper, all while maintaining quality". On Azure, Microsoft documents semantic caching for Azure OpenAI through API Management (an embeddings backend plus llm-semantic-cache-lookup / store policies backed by Redis).

Why it matters on the job: the first question a customer's CFO asks about a successful pilot is "what will this cost at 10x users?" A lead who can say "we'll restructure prompts for caching and add a semantic cache, expected to cut model spend substantially, measured by hit rate" is speaking architect language.

Interview angle

  • "Our RAG bot costs too much. What do you do?" Strong answer: measure token spend per step; reorder prompts for prefix caching; add semantic cache for repeated questions with per-tenant keys; embedding cache for ingestion; smaller model for easy queries; track hit rate, cost and answer quality together.
  • "What can go wrong with a semantic cache?" Strong answer: false hits on similar-looking but different questions, cross-user leakage, staleness; mitigate with threshold tuning on an eval set, scoping, TTL and invalidation on re-index.

Glossary

Token
A chunk of text (about 3/4 of a word) that models read and bill by.
Embedding
A list of numbers representing the meaning of text; similar meanings give nearby vectors.
Cosine similarity / threshold
A 0-1 score of how close two embeddings are / the minimum score you accept as 'same question'.
Semantic cache
A cache looked up by meaning instead of exact text.
Prompt (prefix) caching
Provider-side reuse of the processing of an unchanged prompt start.
Time to first token (TTFT)
How long before the model starts streaming its answer.
Cache hit / miss / hit rate
Found / not found / share of requests served from cache.
TTL
Time to live: how long an entry stays valid.
Invalidation
Removing or refreshing cached entries when the source changes.
Tenant
One customer organisation in a shared (multi-tenant) system.
API Management (APIM)
Azure's API gateway; policies run on every request passing through it.
Vector DB / index
Storage optimised for finding the nearest embeddings.
RAG
Retrieval-augmented generation: fetch relevant documents and include them in the prompt.
