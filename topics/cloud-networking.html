Cloud networking basics: VPC / VNet, subnets, private endpoints, DNS, NAT

What it is and the problem it solves

A virtual private network in the cloud (VPC on AWS and GCP, VNet on Azure) is your own fenced-off address space inside the provider's data centres. You carve it into subnets, decide which parts can be reached from the internet, and connect it privately to managed services, other networks and your office. Without it, databases and AI endpoints sit on public addresses protected only by passwords and keys.

How it works

  1. Address plan (CIDR)Pick a private range like 10.0.0.0/16 (about 65,000 addresses) and split it into subnets like 10.0.1.0/24 (256). Plan ranges so they never overlap with other networks or the customer's office, or you cannot connect them later.
  2. Public vs private subnetsOnly the front door (load balancer, gateway) lives in a public subnet. App servers, databases and workers live in private subnets with no public IPs.
  3. Route tablesEach subnet has rules saying where traffic for each destination goes: inside the network, to the NAT gateway, to a hub, or to the office.
  4. Private endpoints + private DNSA private endpoint gives a managed service (Azure OpenAI, a storage account, RDS) an IP inside your subnet. Private DNS makes the service's normal hostname resolve to that IP, so code does not change. Forgetting the DNS part is the most common reason 'it still goes over the internet' or 'it cannot connect'.
  5. Hub and spokeLarge organisations put shared things (firewall, VPN, DNS) in a hub network and connect each app's spoke network to it, instead of peering everything with everything.
Everyday comparison: a gated apartment complex.
The VPC is the gated complex; subnets are the towers; firewall rules are the guards checking who may enter which tower. The main gate with security is the public subnet's load balancer. The NAT gateway is the residents-only exit: you can drive out to the market, but no outsider can drive in through it. A private endpoint is a shop the supermarket opened inside the complex, so you never step onto the public road. Private DNS is the intercom directory that sends 'Supermarket' to the in-complex shop, not the one in town.

Pattern card: private-by-default landing zone (hub and spoke)

What it is
A hub network holds shared firewall, DNS and on-prem links; each application gets a spoke network with private subnets and private endpoints; only the load balancer is public.
Metaphor
A gated township: one main security gate and utility hub, many apartment towers connected by internal roads.
Real example
Slack's 'Whitecastle' redesign replaced hundreds of peered VPCs with shared VPCs per region connected through AWS Transit Gateway (Slack engineering blog, 2020 and retrospective).
Use when
Enterprise customers, many teams or apps, regulated data, hybrid with an on-prem data centre.
Do not use when
A single small app or prototype; the overhead outweighs the benefit.
Trade-offs
Strong isolation and central control vs cost, DNS complexity and a central hub to scale and monitor.
Instruction to AI / a teammate
In Terraform, create a spoke VNet 10.20.0.0/16 peered to the hub, with app and data subnets that have no public IPs, private endpoints plus private DNS zones for Azure OpenAI, Storage and PostgreSQL, a NAT gateway for outbound, and public access disabled on every one of those services.

Real-world scenario: Slack's Whitecastle network on AWS

Slack's engineering blog post \"Building the Next Evolution of Cloud Networks at Slack\" (September 2020) describes how the network grown from a few hand-built EC2 instances became hundreds of peered VPCs that were painful to manage. The redesign, Whitecastle, created VPCs in networking accounts, each with two /16 address ranges (over 130,000 IP addresses per region), shared them with child accounts, and connected regions with AWS Transit Gateway inter-region peering, all automated in Terraform. Every VPC got one simple route, 10.0.0.0/8 to its local Transit Gateway, because all ranges were planned inside that summary range. Legacy VPCs were attached to the same Transit Gateways so teams could migrate gradually instead of in one big bang (the strangler fig idea from drop 4). The retrospective a year later adds the operational lessons: monitoring Transit Gateway CloudWatch metrics such as dropped packets per attachment, and working with AWS to scale Transit Gateways for bursty traffic.

Why it matters on the job
When you deploy into a customer's cloud, their network team owns the hub, the address ranges and the firewall. Knowing to ask early for a non-overlapping CIDR range, a private endpoint for the model API and the DNS setup is often the difference between deploying in a day and waiting three weeks on a ticket queue.

FDE / architect interview angle

  • A bank wants our RAG assistant in their Azure tenant with no public endpoints. Draw the network. Strong answer: spoke VNet peered to their hub; front door through Application Gateway with WAF (or internal only via VPN/ExpressRoute); app in private subnet (Container Apps with VNet integration); private endpoints + private DNS for Azure OpenAI, AI Search, Storage, PostgreSQL with public access disabled; outbound via their hub firewall or NAT; managed identities for auth; logs to their Log Analytics.
  • Our app cannot reach the database after we added a private endpoint. Where do you look? Strong answer: DNS first (does the hostname resolve to the private IP from inside the app's network?), then firewall rules / NSGs / security groups on the port, then route tables and peering, then the service's own firewall or public-access setting.

Glossary

VPC / VNet
Your private network inside a cloud provider (AWS and GCP / Azure names).
Subnet
A smaller block of addresses inside the VPC, usually public or private.
CIDR (/16, /24)
Notation for an address range; smaller suffix = bigger range (/16 is about 65,000 addresses, /24 is 256).
Private IP
An address only reachable inside the network (10.x, 172.16-31.x, 192.168.x).
Route table
Rules telling traffic where to go next for each destination.
Security group / NSG
Firewall rules attached to resources or subnets.
NAT gateway
Lets private servers make outbound internet calls without being reachable from outside.
Private endpoint / PrivateLink / Private Service Connect
A private IP inside your network for a managed service.
DNS / private DNS zone
The internet's phone book / a private version that maps names to private IPs.
Peering
A direct private link between two networks; not transitive.
Transit Gateway / Virtual WAN / Network Connectivity Center
Central hubs that connect many networks.
Hub and spoke
Topology with shared services in a hub and each app in its own spoke.
Landing zone
A pre-built, governed cloud setup (accounts, networks, policies) teams deploy into.
VPN / ExpressRoute / Direct Connect / Interconnect
Encrypted tunnel / dedicated private lines from an office or data centre to the cloud.
Availability zone
A separate data centre within a region.
Managed identity
An Azure identity for an app, so no passwords in code (drop 1, drop 7).
